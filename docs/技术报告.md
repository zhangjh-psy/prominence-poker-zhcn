# Prominence Poker 简体中文汉化 · 技术可行性分析与实施方案

> 分析方式：直接读取本机安装文件的真实结构（非推测）
> 结论日期：2026-11-15

## 0. 结论速览

**可行性：高。这属于汉化难度最低的一类游戏——没有打包、没有加密、没有反作弊，文本和字体都是明文散文件。**

| 关键问题 | 实测结论 |
|---|---|
| 引擎 | Unreal Engine 4（存在 `Prominence.uproject`、`Saved/` 目录结构、`-Win64-Shipping.exe`） |
| 资源打包方式 | **完全不打包**。无任何 `.pak` / `.utoc` / `.ucas`，全部为散装 `.uasset/.uexp/.ufont` |
| 文本存放 | `Prominence/Content/Localization/Game/<lang>/Game.locres`，标准 UE4 LocRes **v3** 格式 |
| 是否加密 | **否**。locres 为明文，文件头 magic + 可读键名，无 AES、无压缩、无签名 |
| 是否有校验 | **无运行时校验**。仅 Steam 客户端「验证文件完整性」会按 depot 清单还原原文件 |
| 反作弊 | **未发现** EasyAntiCheat / BattlEye 任何组件（游戏目录内无相关文件） |
| 语言数量 | en / de / es / fr / it，共 5 套，均在磁盘上 |
| 中文语言槽 | 无 `zh-Hans` 目录；语言映射表硬编码在 exe 内（仅 5 条） |

**一句话：不需要拆包、不需要 AES 密钥、不需要重打包，只需要替换一个 locres 文件 + 处理 4 个字体的中文回退。**

### 1.2 为什么"散装"是决定性的好消息

常规 UE4 游戏汉化需要：`FModel 拆 pak → 改 locres → UnrealPak 重打包 → 用 _P.pak 覆盖优先级`。
本作全部跳过：**locres 就在磁盘上，改完即生效，无需重打包、无需处理 AES 密钥**。

如果哪天官方改回 pak 打包（可能性低但存在），则退回标准流程：`FModel` 导出 → 修改 → `UnrealPak` 打包 → 命名为 `<原pak名>_P.pak` 放入 `Content/Paks/`（`_P` 后缀会被 UE 判定为高优先级补丁，覆盖同名资源）。

## 2. 文本资源：LocRes v3 结构实测

`Game.locres` 的文件头已逐字节验证：

| 偏移 | 长度 | 字段 | 实测值（en） |
|---|---|---|---|
| 0x00 | 16 | Magic GUID | `0E147475 674A03FC 4A15909D C3377F1B` |
| 0x10 | 1 | Version | `0x03`（Optimized_ReplaceDiffWithEntryArray） |
| 0x11 | 8 | StringTableOffset (int64) | `60669` |
| 0x19 | 4 | EntryCount (uint32) | `1718` |
| 0x1D | 4 | NamespaceCount (uint32) | `4`（GameST / PlatformST / PlatformSTPS4 / PlatformSTXB1） |
| 0x21 | … | 命名空间记录 + 其条目**交错存放** | … |
| 60669 | … | 字符串表 | `1550` 条唯一串 |

字符串表内部格式已完整解析并验证（解析 1550 条后**恰好落在文件末尾 165321 字节**，说明结构判断无误）：

```
[uint32 count=1550]
重复 count 次：
  [int32 len]   // len>0: UTF-8，len 含结尾 \0；len<0: UTF-16LE，长度为 -len
  [bytes 文本]
  [uint32 refCount]   // 1=仅一处使用，2~5=被多条键复用
```

### 2.1 关键含义

1. **编码是最大的坑，必须用 UTF-16LE**。UE 的 `FString` 序列化规则是：**正长度 = ANSI（一个字节一个字符），负长度 = UTF-16LE**。把中文写成 UTF-8 正长度，游戏会按 ANSI 逐字节拆开，每个字节变成一个独立字符，字体里没有这些拉丁扩展字形，于是渲染成一串问号——**问号个数等于 UTF-8 字节数**（4 个汉字 = 12 个问号）。
   正确做法：含非 ASCII 字符的串一律用 `enc='u16'`（负长度）。西语/德语/法语文件里 500–700 条带重音的串全部是 UTF-16，可直接对照验证。
2. **文本是明文的**，键名肉眼可读，命名规范统一：
   - `LBL_*` 标签 / `BTN_*` 按钮 / `DESC_*` 描述 / `FORMAT_*` 格式化串 / `FUE_*` 前端引导（First User Experience）/ `PROFILE`、`VIEW PROFILE` 等全大写短串。
3. **有字符串复用（dedup）**。1550 条唯一串支撑 1718 个键，说明同一句被多处引用。翻译时需注意：**一个串改了，所有引用它的位置都会变**，不能按"这个按钮该叫 A、那个按钮该叫 B"来差异化。
4. **条目按"下标"引用字符串，不是按字节偏移**。这是关键——意味着中文译文可以任意长/短，不需要回填任何指针，字符串表可整段重写。写入风险因此极低。（见附录 A.2）
4. **单条最长 10,967 字符**（大概是用户协议/法律文本）。这类内容建议人工决定是否翻译，机翻容易产生误导性法律表述。

### 2.2 文本里的富文本标记（必须原样保留）

1550 条中有 **54 条（3%）** 含自定义标记，例如：

```
##The Mayor## has **Gifted** you a &&Mediocre Tourist Tea&& **Table Item**!
##The Mayor's## action has **Cancelled** your **Preset** action.

**Preset** can also be cancelled manually by clicking the **Cancel** button.

To continue, [Bet]&&Raise&& **2K**.
```

| 标记 | 用途 | 处理要求 |
|---|---|---|
| `##…##` | 名词/人名高亮 | 保留标记，只翻译内部文字 |
| `**…**` | 加粗 | 保留 |
| `&&…&&` | 次级高亮（动作/物品名） | 保留 |
| `{Line#Header}` | 换行/排版控制 | **禁止翻译或删除** |
| `[Bet]` | 输入提示/图标占位 | 保留，可译内部词 |
| `\n` | 硬换行 | 按中文语序重排即可 |

> 破坏这些标记轻则排版错乱，重则**蓝图字符串解析异常导致界面空白**。建议在 CAT 工具里把这些标记设为"不可译标签"。

## 3. 语言加载机制：为什么推荐"覆盖 en"

### 3.1 实测发现

`Prominence-Win64-Shipping.exe` 内存在一张**静态语言映射表**（相邻存储，成对出现）：

```
french  → fr-FR
italian → it-IT
german  → de-DE
spanish → es-ES
(默认)  → en-US
```

同时：

- locres 里**不存在** "Language / 语言 / English / Deutsch" 等任何语言选项文案 → **游戏内没有语言切换菜单**；
- exe 内**不存在** `schinese` 字符串 → 简体中文不在支持列表内；
- 因此语言由 **Steam 客户端语言 / 系统区域**决定，未命中则回落 `en-US`。

### 3.2 三种落地策略对比

| 方案 | 做法 | 优点 | 缺点 | 建议 |
|---|---|---|---|---|
| **A. 覆盖 `en`** | 把中文写进 `Content/Localization/Game/en/Game.locres` | 100% 生效（en-US 是默认回退）；改动最小；不受 Steam 语言影响 | 游戏内无法切回英文，需换文件 | **推荐** |
| B. 新增 `zh-Hans` | 建 `zh-Hans/Game.locres` + 改 `Game.locmeta` + 改 `DefaultGame.ini` 的 `CulturesToStage` | 理论上最"正规"，可与英文共存 | **exe 里没有 zh 映射，大概率加载不到**；且 `CulturesToStage` 是 cook 期配置，运行时不一定生效 | 可先花 10 分钟试，失败即回退 A |
| C. 借壳 de/es/fr/it | 中文写进 `de`，再把 Steam 语言设为德语 | 英文槽位保留，等于双语言 | 需要改 Steam 全局语言，体验割裂 | 进阶玩法 |

**推荐 A，并保留原文件做开关**：目录里同时放 `Game.locres`（当前生效）与 `Game.locres.en.bak`（英文原件），用一个小脚本切换。

> 若想试方案 B：`Game.locmeta` 结构为 `magic(16B) + version(1) + FString "en" + FString "en/Game.locres" + uint32 count(5) + 5×FString("de","en","es","fr","it")`，追加 `zh-Hans` 是纯字符串追加，技术上可改，但**是否被读取取决于 exe 而非文件**，所以别抱太大期望。

## 4. 字体与编码适配

### 4.1 已确认的字体架构

游戏 UI 使用 UE4 的**复合字体（CompositeFont）**：每个字体族一个 `.uasset`（复合），内部由「主字形 + 回退字形链」组成；具体字形数据在独立 `.ufont` 文件里，**是裸字体文件**（`Anton_Noto_Unicode_.ufont` 直接以 `00 01 00 00` 开头，是标准 TrueType；`NotoSansSC-Regular.ufont` 以 `OTTO` 开头，是 CFF/OpenType）。`.uexp` 里存的是**相对路径引用**：

```
../../../Prominence/Content/UI/FONTS/NotoSansSC-Regular.ufont
```

**这意味着：替换 `.ufont` 文件内容即可更换字形，不需要改任何 uasset。**

### 4.2 各字体族的中文覆盖情况

| 字体族 | 用途（推断） | 回退链是否含中文 |
|---|---|---|
| `Bitter` | 正文（最大量） | ✅ 含 `NotoSansSC-Bold` / `NotoSansSC-Regular` |
| `Anton` | 标题/展示字 | ⚠️ 仅回退 `Anton_Noto_Unicode_`（457KB，无 CJK） |
| `GeoSlab703` | 数字/牌桌信息 | ❌ 无任何 Noto 回退 |
| `CooperHewitt` | 次级标题 | ❌ 无 |
| `Galderglynn` | 装饰/Logo 类 | ❌ 无 |
| `*_Username_Font` | 玩家名/聊天 | ✅ 含 JP/KR/Arabic/SC 等 |

**结论：正文中文大概率开箱即用；标题类会出"豆腐块"（□□□），需要单独处理这 4 个字族。**

### 4.3 三种字体修法（按侵入性排序）

**F1 · 直接换 `.ufont`（5 分钟，先验证）**
把缺 CJK 的字族的 `.ufont` 备份后，替换为 `NotoSansSC-Regular.ufont` 的副本。
- 优点：零工具依赖，纯文件拷贝，立刻能看出问题在哪
- 缺点：英文字形风格变成 Noto Sans（不好看但可读）
- 用途：**作为诊断手段**，快速确认"哪几个字体族真的缺字"

**F2 · 字体合并（推荐，兼顾美观）**
用 `fontTools` 把「原字体（拉丁）+ Noto Sans SC（中文）」合并成一个字体，替换原 `.ufont`：
```bash
# 1) 按译文用到的字，子集化中文字体（大幅缩小体积）
pyftsubset NotoSansSC-Regular.otf --text-file=used_chars.txt \
    --output-file=sc_subset.otf --layout-features='*'

# 2) 若需与 TrueType 合并，先转曲轮廓
otf2ttf sc_subset.otf -o sc_subset.ttf    # 或用 fontTools cu2qu

# 3) 合并：拉丁用原字体，CJK 用 Noto
fonttools merge -o Anton_0_Regular.merged.ttf Anton_0_Regular.ttf sc_subset.ttf
```
- 优点：英文保持原设计风格，中文用 Noto，观感接近商业本地化
- 注意：`NotoSansSC` 是 CFF/OTF，与 TrueType 直接 merge 可能报轮廓不兼容，需先转 TTF；合并后建议用 `fonttools ttLib` 校验 `cmap` 完整性

**F3 · 改复合字体资源（最规范）**
用 `UAssetGUI` 打开 `Anton.uasset` / `GeoSlab703.uasset` 等，在 `CompositeFont.FallbackTypeface` 数组里追加一条 `FTypefaceEntry`，`FontFaceAsset` 指向已存在的 `/Game/UI/FONTS/NotoSansSC-Regular`。
- 优点：与引擎原生机制一致，正文/标题自动分流，不改变任何英文字形
- 缺点：需要理解 uasset 属性结构，改错会导致字体资源加载失败（做好备份）
- **这是最接近官方做法的方案**

### 4.4 编码与排版细节

- **编码**：**中文必须写 UTF-16LE（负长度）**，纯 ASCII 才用 ANSI（正长度）。这是本项目踩过的最大的坑，详见附录 C。游戏 UI 基于 Slate + ICU，原生支持 CJK 断行，**不需要**像老式游戏那样手工插换行。
- **标点**：用全角 `，。！？：；「」""`；数字/英文与中文之间加空格（`获得 500 筹码`）。
- **字号**：中文同字号视觉偏大，但改字号要动 uasset，**建议第一版不动**，靠译文长度控制。
- **行高**：若出现中文上下被裁切，说明该字体族的行高（leading）按拉丁字设计，需要在 F3 里调 `LegacyFontSize`/行距，或在 F2 合并时调整 `hhea` 的 ascender/descender。
- **长度**：中文通常比英文短 30–50%，固定宽度按钮一般不会溢出；**风险在长描述句 + 小面板**（如牌桌提示、商店物品说明），需实机逐条看。

## 5. 实施步骤

### Step 0 · 准备与备份（5 分钟，必做）

```bash
GAME="/d/steam/steamapps/common/Prominence Poker"
BAK="$HOME/prominence_i18n_backup"
mkdir -p "$BAK"
cp -r "$GAME/Prominence/Content/Localization" "$BAK/"
cp -r "$GAME/Prominence/Content/UI/FONTS" "$BAK/"
cp "$GAME/Prominence/Config/DefaultGame.ini" "$BAK/"
```
> 同时建议：Steam → 该游戏 → 属性 → 更新 → 关闭「自动更新」，避免改到一半被覆盖。
> 回滚 = 把备份拷回原路径。**这是唯一的救命绳，务必先做。**

### Step 1 · 提取文本

散装文件的好处：**不用 FModel 拆包**，直接把 locres 拖进工具。

- 工具 A：`UnrealLocres`（Python CLI，支持 locres ↔ csv/json 互转）
- 工具 B：`UE4LocalizationsTool`（GUI，`File → Open` 直接开 `.locres`，`Tools → Export all text`）

产出：一张 `key, source_en, target_zh` 的 CSV/TSV（约 1718 行）。

> 注意：不同工具对 v3 格式的导出完整度有差异。**导出后必须核对行数是否 = 1718**，若明显偏少说明工具没支持该版本，换工具或升级版本。

### Step 3 · 翻译

建议流程：**LLM/机翻初稿 → 人工通读 → 术语一致性校验 → 标记校验**。

三条硬规则：
1. **富文本标记原样保留**（54 条需人工复核）；
2. **`{…}` 占位符与 `%s`/`%d` 一个字符都不能动**；
3. **字符串复用**：1550 条唯一串支撑 1718 键，改一条会影响多处，不要按场景差异化措辞。

法律/协议类长文本（最长 10,967 字符）建议：要么全文精译，要么保留英文并加中文摘要——机翻法律条款有实际风险。

### Step 4 · 回写 locres

- 用同一工具 `Import` 回 CSV，保存为 `Game.locres`
- **关键校验**：回写后文件能被工具重新打开且条目数仍为 1718；文件大小会变（中文 UTF-8 每字 3 字节），这是正常的——工具会重算字符串表偏移
- 覆盖 `Content/Localization/Game/en/Game.locres`

### Step 5 · 字体

1. 先按 **F1** 快速替换 4 个缺字字族的 `.ufont`，启动游戏看标题是否还出豆腐块 → 确认问题范围
2. 再按 **F2 或 F3** 做正式版
3. 字体体积提示：`NotoSansSC-Regular.ufont` 有 8.4MB，全量替换会让目录变大；用 `pyftsubset` 按实际用字子集化后通常只有 **300–800KB**

### Step 6 · 界面与排版微调

不需要改布局，但需要**逐屏检查**。优先级：

| 优先级 | 界面 | 关注点 |
|---|---|---|
| P0 | 主菜单 / 大厅 | 标题字体豆腐块、按钮文字截断 |
| P0 | 牌桌 HUD | 行动按钮（Fold/Call/Raise）宽度、倒计时、盲注数字 |
| P0 | 设置 / 选项 | 选项名过长、开关键盘提示 |
| P1 | 商店 / 道具 | 物品名 + 描述两行是否挤压 |
| P1 | 剧情模式 | 对话气泡、过场字幕 |
| P2 | 通知 / Toast | 弹窗宽度固定，长句换行 |
| P2 | 成就 / 排行榜 | 数字与中文混排 |

### Step 7 · 打包分发（可选）

- 自用：直接改文件即可
- 分享：只打包 `Content/Localization/Game/en/Game.locres` + 被替换的 `.ufont`，附带一个安装/卸载 `.bat`，**不要打包整个 Content**
- 命名建议：`ProminencePoker_zhCN_v1.0.zip`，内含 `install.bat` / `uninstall.bat` / `README.txt`

## 7. 风险与注意事项

### 7.1 账号与合规

- **未发现反作弊组件**，纯文本替换不触碰游戏逻辑，被判定为作弊的可能性极低；
- 但修改客户端文件**可能违反 EULA**（几乎所有在线游戏的用户协议都禁止修改客户端）。**风险不为零，自行判断**；
- 本作是联网游戏（Pipeworks 服务器存档），**不要**同时改动任何与筹码/进度/对战逻辑相关的资源，那才是真正的高危区；
- 不建议在公开对局中展示明显异常（如字体渲染错误导致的界面空白），容易被举报。

### 7.2 技术风险

| 风险 | 说明 | 应对 |
|---|---|---|
| **Steam 更新覆盖** | 游戏更新会覆盖 locres 与字体文件 | 保留源 CSV + 一键重放脚本；Steam 关闭自动更新 |
| **Steam 验证完整性** | 会按 depot 清单还原所有被改文件 | 校验后重新安装汉化包 |
| **工具不支持 v3** | 部分老版 locres 工具只支持 v1/v2，导出会缺条目或写坏 | 导出后核对 1718 行；写坏就用备份回滚 |
| **偏移计算错误** | 中文变长后字符串表偏移需重算，工具 bug 会导致文件损坏 | 每次回写后先用工具重新打开验证；先在副本上试 |
| **富文本标记被破坏** | 可能造成界面空白/蓝图字符串异常 | 建立标记白名单，脚本自动校验 |
| **字符串复用** | 一条串多处引用，措辞无法差异化 | 术语表先行，接受"通用化"措辞 |
| **标题字体豆腐块** | 4 个字族无 CJK 回退 | F1/F2/F3 三种方案 |

### 7.3 内容本身的限制（改不了的部分）

- **玩家昵称、聊天内容、部分服务器推送消息**：由服务器下发，客户端静态文本无法翻译；
- **图片内嵌文字**：Logo、桌面贴图、部分宣传图上的英文是烘焙进贴图的，要改需导出 PNG → 改图 → 重新导入为 uasset（工作量大，通常不做）；
- **`BrandMovie01.mp4`**：唯一视频，若有烧录字幕无法处理（目前看是品牌片，一般无关键文本）；
- **语音**：本作无中文语音，且只有英配，无需处理；
- **字幕**：走 `BP_SubtitlesData`，文本应在 locres 内，随主流程一起翻译。

## 8. 版本更新维护方案

核心思想：**翻译成果与游戏文件解耦，始终以 CSV 为唯一真相源。**

```
project/
├─ source/
│  ├─ en_v2026-11-15.locres      # 每次更新后从游戏目录复制一份原始 en
│  └─ en_v2026-11-15.csv         # 由上面导出
├─ translation/
│  └─ zh.csv                     # 唯一真相源（key, en, zh, status, note）
├─ build/
│  └─ Game.locres                # 由 zh.csv + 当前 en 生成
└─ tools/
   ├─ export.py  import.py  diff.py  install.py
```

**每次游戏更新后的标准动作（约 10 分钟）：**

1. 复制新的 `en/Game.locres` 到 `source/en_v<日期>.locres`
2. 导出为 CSV，与上一版 CSV 做 **key 集合 diff**：
   ```python
   old = {r['key'] for r in csv.DictReader(open('source/en_prev.csv'))}
   new = {r['key'] for r in csv.DictReader(open('source/en_cur.csv'))}
   print("新增:", len(new-old), "删除:", len(old-new))
   ```
3. 新增 key → 补译；删除 key → 从 zh.csv 标记 `deprecated`（不要直接删，可能回归）
4. 已译 key 若 **英文原文变了**，标记 `needs_review`（原文变化常意味着玩法改动）
5. 用 `zh.csv` 重新生成 locres → 覆盖 → 抽查 3 个界面
6. 记录版本号：`zh.csv` 首行注释写入 `# base=en_v2026-11-15`

**字体只需做一次**，除非官方新增字体族（届时 `diff` 一下 `UI/FONTS` 目录即可）。

> 进阶：把上面 6 步写成一个 `make.ps1`，每次更新一条命令重出汉化包。这套流程成熟后，单次维护成本可压到 5 分钟以内。

1. 收集全部译文用字（78 个汉字）+ ASCII + 中文标点 → 193–200 字符；
2. `pyftsubset` 生成常规/粗体两个子集（各约 78–80KB）；
3. 覆盖 UI 各字体族的 `.ufont`（共 43 个，其中 16 个按文件名判定用粗体子集）；
4. **路径不变**，`.uexp` 的相对引用依然有效，**不需要改任何 uasset**。

文件总量 4.6MB → 3.5MB，反而更小。

### B.4 重要工作流规则

> **每次新增译文中出现「之前没用过的汉字」时，必须重新运行 `tools/make_cjk_fonts.py`**，

## 附录 C · 第三轮：问号的真正原因（编码，不是字体）

### C.1 决定性证据：问号的个数

第二轮截图里，问号数量与**文本字节数**完全对应：

| 中文 | 字数 | UTF-8 字节 | 屏幕上问号数 |
|---|---|---|---|
| 快速开始 | 4 | 12 | 12 |
| 商店与仓库 | 5 | 15 | 15 |
| 角色 | 2 | 6 | 6 |
| 排行榜 | 3 | 9 | 9 |
| 帮助与选项 | 5 | 15 | 15 |

一个 `?` 对应一个字节，而不是一个字符 → 文本被**逐字节**当成独立字符处理了。

### C.2 根因

UE 的 `FString` 序列化规则：

```
SaveNum = IsPureAnsi() ?  (Len + 1)      // 正长度，ANSI，1 字节 1 字符
                        : -(Len + 1)     // 负长度，UTF-16LE，2 字节 1 字符
```

我第一版把中文按 **UTF-8 + 正长度** 写入。游戏按 ANSI 解读 → 4 个汉字变成 12 个拉丁扩展字符 → 字体里没有这些字形 → 12 个问号。

**验证方式**：检查官方译文。`es` 有 673 条、`de` 有 525 条、`fr` 有 714 条字符串是 UTF-16（负长度），全部是带重音符号的串；**没有任何一条**用 ANSI 存非 ASCII 字符（`en` 里那 33 条例外是官方自身的数据瑕疵）。

### C.3 修复

`build_patch.py` 中：

```python
lr.strings[si].enc = "u16" if any(ord(c) > 0x7F for c in zh) else "u8"
```

并在构建后回读校验 `enc` 是否与内容匹配。十六进制确认：

```
长度字段: fb ff ff ff  ->  -5   （4 字 + 结尾空字符 = 5 个码元）
字节    : eb 5f 1f 90 00 5f cb 59
解码    : 快(5FEB) 速(901F) 开(5F00) 始(59CB)
```

### C.4 下一次启动的判读方法

| 现象 | 结论 |
|---|---|
| 显示「快速开始」等中文 | ✅ 全部打通 |
| 显示 **4 个** `?`（而不是 12 个） | 编码已修复，但字体未被使用 → 查字体替换是否生效 |
| 仍显示 **12 个** `?` | 编码没生效 → 检查是否有其他 locres 覆盖 |
| 显示乱码（å¿« 之类） | 被当成 Latin-1 解码 |

问号的**个数**是最快的判据。

### C.5 附带发现

- 主菜单 `LOOT CASES` 用的是 `TITLE_LOOT_CASES`（idx 651），不是 `LBL_LOOTCASES`（652 带 `{0}` 计数）。同类「同名不同键」的情况在汉化时要以实际控件引用的键为准——用 `BP_*.uasset` 里 grep 键名比猜更可靠。
- 引擎层另有 `Engine.locres` 与若干插件 locres（`OnlineSubsystem*`），仅含 en/es/de/fr/it，属引擎级字符串，与游戏 UI 无关。

| `build/install.bat` / `uninstall.bat` | 一键安装/还原 |

### D.6 后续新增译文的流程

```
1. 在 translation/zh_*.py 中加条目（键为字符串下标）
2. python tools/apply_zh.py backup/Localization_original/Game/en/Game.locres build/Game.locres --report
3. python tools/make_cjk_fonts.py        # 若有新汉字，必须执行
4. 复制 build/Game.locres 到游戏
```

> 第 3 步不可省略：字体是子集，新出现的汉字不重跑就会显示成问号。
